# LG PuriCare 360 (`AIR_910604_WW`) — reference Lua handler

**This is the reference example for writing a UALC Lua device handler.** Copy
it as a starting point; `handler.lua` is commented for that purpose.

## Status — read this before believing anything

| | |
|---|---|
| Support level | `DECODED` |
| Verification source | `none` |
| Hardware tested | **no — never, not once** |
| Fixtures | **synthetic**, generated by this project's own encoder |
| Can it send commands? | **no** |

It has never been run against a physical appliance. Its presence in this
repository is **not** a claim that UALC controls an LG purifier.

## What it does

Decodes LG ThinQ2 `0xA7` TLV frames into named fields: power, mode, fan
speed, PM1/PM2.5/PM10, air-quality and odour indices, error code, and the two
main filter counters. It distinguishes full-state frames from delta frames,
reports out-of-domain enum values instead of coercing them, counts
unrecognised tags, and flags truncated frames.

## What it deliberately does not do

**No `build_outbound`.** The outbound frame carries a trailing 16-bit checksum
whose polynomial this project has not independently verified, and emitting
unverified bytes at real hardware is the one thing a decoder must not do. So
the handler declares a read-only capability set: eight of the nine contract
operations.

That is a **supported outcome, not a gap** — UALC asks a plugin to declare
what it implements rather than assuming every appliance exposes the same
operations, and `adapter_contract_test.py` asserts that `build_outbound`
raises `NotImplementedError` here. This example exists partly to prove partial
implementations are first-class.

It also does not validate the inbound checksum (on real hardware the Wi-Fi
module does that before the frame reaches us), and it rejects the `0x87`
dialect explicitly rather than mis-decoding another appliance class.

## Same device, two ways

There is also a Level-1 declarative profile for this model at
[`../../../../devices/lg/AIR_910604_WW.json`](../../../../devices/lg/AIR_910604_WW.json).
`testing_infra/adapter_contract_test.py` runs **one** set of cases against
both and requires they agree.

That equivalence is the evidence that the plugin contract is genuinely
language-neutral. Writing it also caught two real bugs before either shipped:
a truthiness test on `power` that would have reported an undocumented value
as `on`, and a garbled bounds check in the Python codec.

If you are deciding between Level 1 and Level 2 for your own device: this
model honestly only needs the **profile**. The handler exists as a teaching
example and as the place where quirks would go if the device had any that a
table could not express.

## Provenance and licence

MIT, like the rest of UALC.

The TLV framing and tag numbers are protocol **facts** from this project's own
LG research, corroborated by public reverse-engineering discussion in the
`anszom/rethink` project (notably its `AIR_910604_WW` pull request). rethink is
GPL-2.0 and **no code, comment text or captured fixture from it has been
copied** into this handler or this repository. This is an independent
implementation of a wire format written against a field list, which is why it
is MIT-licensable.

If you contribute a handler derived from someone else's GPL code, say so in
your pull request — we cannot merge it under MIT, and we would much rather
have that conversation than a licence violation in the tree.

## Run it

```bash
PYTHONPATH=translator:testing_infra:. python testing_infra/adapter_contract_test.py
PYTHONPATH=translator:testing_infra:. python testing_infra/plugin_security_test.py

# what the handler advertises about itself
PYTHONPATH=translator:. python translator/lua_host.py \
    plugins/lua/examples/lg_air_910604_ww/handler.lua
```

Needs Lua 5.4+ on PATH. Without it the suites skip rather than fail.
